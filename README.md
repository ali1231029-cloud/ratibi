# راتبي — إدارة الراتب والمصاريف والادخار

تطبيق ويب عربي (RTL) يعمل على الهاتف والكمبيوتر، ويمكن تثبيته على الشاشة الرئيسية (PWA) والعمل دون إنترنت.

## التشغيل

```bash
npm install
npm run dev        # للتطوير: http://localhost:5180 (أو المنفذ الذي يظهر)
npm test           # اختبارات الحسابات والتخزين والنسخ الاحتياطي
npm run build      # نسخة الإنتاج في مجلد dist/
npm run preview    # تشغيل نسخة الإنتاج محلياً
```

مجلد `dist/` ملفات ثابتة فقط، يمكن رفعها إلى أي استضافة (Vercel أو Netlify أو GitHub Pages). التثبيت على الهاتف والعمل دون إنترنت يحتاجان رابط HTTPS.

## التقنيات

- React 18 + TypeScript + Vite
- قاعدة البيانات: IndexedDB عبر Dexie (قاعدة باسم `ratibi` داخل المتصفح)
- لا خادم، ولا حساب، ولا إرسال لأي بيانات إلى الخارج

## أين تُحفظ البيانات وما حدود ذلك

- كل البيانات محفوظة في IndexedDB داخل المتصفح على الجهاز نفسه، وتبقى بعد إعادة التحميل وإغلاق التطبيق وإعادة تشغيل الجهاز.
- يطلب التطبيق من المتصفح «تخزيناً دائماً» حتى لا تُحذف البيانات عند امتلاء المساحة. تظهر الحالة في الإعدادات.
- **الحدود:** البيانات مرتبطة بهذا المتصفح على هذا الجهاز. لا توجد مزامنة بين الأجهزة. مسح بيانات المتصفح، أو التصفح الخاص، أو تغيير الجهاز يعني فقدان البيانات ما لم تكن هناك نسخة احتياطية.

## النسخ الاحتياطي والاستعادة

- **الإعدادات ← إنشاء نسخة احتياطية كاملة (JSON):** ينزّل ملفاً فيه كل شيء. احفظه خارج الجهاز (Google Drive أو البريد أو حاسوب آخر).
- **تصدير CSV / Excel:** كل العمليات بترميز UTF-8 مع BOM، فيفتحها Excel بالعربية بشكل صحيح.
- **الاستعادة:** اختر الملف، فيتحقق التطبيق من سلامته ويعرض عدد السجلات، ثم:
  - **دمج:** يضيف السجلات غير الموجودة فقط. المطابقة بالمعرّف الثابت، فلا يتكرر أي سجل.
  - **استبدال:** يستبدل كل البيانات بعد تحذير، ويحفظ قبلها نسخة تلقائية من البيانات الحالية (آخر 5 نسخ) يمكن الرجوع إليها من الإعدادات.
- على جهاز جديد: شاشة الإعداد الأولى فيها خيار «لديك نسخة احتياطية؟ استعدها بدلاً من الإعداد».

## النموذج المالي (مصدر واحد للحسابات: `src/lib/finance.ts`)

كل الصفحات تقرأ أرقامها من الدالة نفسها `computeCycleSummary`:

```
الأموال الداخلة       = المرحّل + الراتب + الدخل الإضافي + أموال ديون مستلمة
المال المتاح فعلياً   = الأموال الداخلة − المصروفات المدفوعة (بعد الاسترداد)
                        − صافي التحويل للادخار − ديون مدفوعة − المرحّل للدورة التالية
المتاح للصرف          = المال المتاح − فواتير الدورة غير المدفوعة − الادخار المخطط غير المحوَّل − الاحتياطي
ميزانية اليوم         = (المتاح للصرف + مصروف اليوم المتغير) ÷ الأيام المتبقية مع اليوم
```

- الفاتورة غير المدفوعة **محجوزة** وليست مصروفاً. عند دفعها تصبح مصروفاً ويزول الحجز، فلا تُخصم مرتين.
- التحويل إلى الادخار **تحويل داخلي** يحل محل الادخار المخطط، فلا يُخصم مرتين، ولا يُحسب مصروفاً.
- الاسترداد يُنقص المصروف ولا يُعد دخلاً. الديون تحرّك النقد لكنها ليست دخلاً ولا مصروفاً.
- المبالغ أعداد صحيحة (الدينار هو أصغر وحدة مستخدمة)، فلا توجد أخطاء الكسور العشرية في JavaScript.
- التواريخ أيام محلية بصيغة `YYYY-MM-DD`، لا طوابع UTC، فلا يتحول تاريخ العملية إلى اليوم السابق.
- الدورة تبدأ يوم استلام الراتب وتنتهي في اليوم السابق للراتب القادم. العملية تتبع الدورة حسب تاريخها.
- اليوم الذي لم يُسجَّل فيه شيء يظهر «غير مسجل»، ولا يُعتبر صرفاً بقيمة صفر.
- إذا لم يتبقَّ يوم في الدورة لا تحدث قسمة على صفر، ويظهر أن الراتب متأخر مع خيار التأكيد أو التمديد.
- عند العجز يظهر العجز بوضوح، وتصبح ميزانية الأيام صفراً بدل رقم موجب مضلل.

## هيكل المشروع

```
src/lib/        money.ts, dates.ts, finance.ts (المحرك المالي), types.ts
src/db/         db.ts (المخطط والإصدارات), repo.ts (كل عمليات الكتابة), backup.ts
src/pages/      الأقسام الثمانية + الديون + الإعداد الأول
src/components/ واجهة مشتركة، رسوم بيانية، نافذة إضافة العمليات
tests/          finance.test.ts, storage.test.ts
```

تغيير بنية قاعدة البيانات يكون بإضافة `version(n)` جديدة مع `upgrade()` في `src/db/db.ts`، ولا يُعدَّل الإصدار 1 أبداً، حتى تبقى بيانات المستخدم بعد التحديث.
